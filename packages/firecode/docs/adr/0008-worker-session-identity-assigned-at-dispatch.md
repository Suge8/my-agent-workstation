# 子代理会话身份由派发方预分配

herdr 的 `agent start` 只保证「进程起来了、屏幕不忙」——固定 3 秒静默期后即返回；Pi 的会话文件路径
是另一条独立信号，由 Pi 侧 herdr 集成在 `session_start` 上报，发生在扩展加载完成之后。两者无因果关系：
实测 Pi 从进程启动到上报耗时 2.3s（空载）到 8.7s（同机八个子代理并行），而就绪阈值恒为 3 秒。原实现在
`agent start` 返回的那一刻要求响应里必须带会话路径，于是满载时每次派发都失败并回收 pane（2026-08-22
事故：连续四次派发成功后第五次起 100% 失败，参数、cwd、worktree 全部无辜）。

据此决定：会话身份是派发的**入参**，不是启动后的观测结果。Master 用官方 `SessionManager.create(cwd)`
预生成会话文件路径（建目录、不落文件），随 `--session` 下发，新建与休眠恢复走同一条路径；Worker 档案
从第一刻起就是会话身份的唯一事实源，herdr 的上报只用于判定身份漂移——上报缺失＝尚未报到，只有报上来的
值与档案冲突才是身份变了，而且凡拿到 herdr agent 记录的路径（启动、reconcile、工作与审查结算）都走同一判据
——否则运行中换了会话时会把上一个会话的旧回复当本轮结果回传。派生结果：结算读回复不再向 herdr 索要路径
（少一次 IPC、少一个事实源），reload 撞上刚启动的子代理也不会因为读不到上报而误判休眠。

启动仍需一道门槛，但它等的是**可用**不是**身份**：Pi 在扩展加载完成前就渲染界面，此时提交只会把文本
塞回输入框（提示 Startup is still in progress）而不执行，长文本还会被终端行缓冲截断（实测 3081 字节只
剩约 1KB）——早投等于任务静默丢失。Pi 的会话上报恰好发生在扩展加载之后，因此以「报到」为投递前提，
60 秒未报到即判启动失败并回收 pane。herdr 只为状态变化提供事件（`agent wait`），会话上报无事件接口，
此处是有界轮询的例外。

状态 schema 随之收紧到 v6（`sessionPath` 全状态必填）。不写迁移，但旧版文件也不得永久阻断激活：
状态所有者丢弃它并从空池重建，只读旁路只招错不删文件，指挥官因此能收到一次“旧池已脱管”的告知。

## 考虑过的选项

`--session-id` 预分配 ID 被否：Pi 仍自行决定文件名与目录，读会话内容要按 ID 反查，等于把耦合从路径
换成查找，且启动时多一行 warning 噪音。自己拼接会话目录路径被否：复刻 Pi 的 cwd→目录名规则是隐式耦合，
官方接口就在宿主包里。只加等待、身份继续用上报值被否：竞态是治好了，双事实源、额外 IPC 与 reload
误判三处同源缺陷仍留在原地，分两次改更贵。
