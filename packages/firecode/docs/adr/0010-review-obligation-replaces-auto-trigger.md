# 审查义务取代落定自动触发

`review:true` 不再表示“Worker 一落定就自动运行 fire-review”，而是把审查义务持久化到该票。指挥官读完结果并确认实现已到可审状态后，显式调用 review；代码保证义务在履行前不能经 ack 消失，并在 reload、中断、失败和继续 send 后保留。通过或质量裁决停止会履行义务；kill 放弃整票时义务随票删除。

自动触发把“落定”误当成“完成”，但模型停下可能是在提问、汇报半成品或等待确认。机器只看到回合结束，无法可靠判断交付是否完整。2026-08-26 的本票给出直接实证：助手停下来确认测试接缝与 Done 条件，零代码改动；旧机制仍把这次对齐提问送入一轮真实对抗审查，两个审查者只能报告“无交付物可评”。这既浪费模型调用，也证明继续增加文本分类或完成度启发式只会把判断风险藏进机制。

据此划清责任：**义务不灭归代码，审查时机归模型。** 代码只维护可验证的不变量——义务持久化、ack 门禁、显式 review 的状态迁移与终态履行；指挥官负责结合工作说明、结果、git 与验证证据判断何时送审。落定事件会明确提示审查义务，但不会替指挥官做完成度判断。

## 后果

重要实现票仍在 start/send 时声明 `review:true`，且 review 不可用时派发前拒绝，避免产生无法履行的承诺。Worker 落定后保持 idle，可先追问、续派、核验或收口，再显式 review。自动补审、审查投递窗口及其恢复分支全部删除；状态机只保留 reviewing 作为真实审查中的运行态。审查事故终态保留义务供重试，质量裁决终态消除义务并回传最终结果。
