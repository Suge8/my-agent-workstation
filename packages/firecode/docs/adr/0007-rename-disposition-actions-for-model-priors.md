# subagents 动作集按模型先验重构：hold→ack、stop 拆分 sleep/kill、新增 interrupt

一次真实事故：Master 对两个正在运行的子代理调用 hold，工具返回成功，Master 与用户都以为它们已"停到待命"，
实际 hold 只消发落标记、对子代理不做任何事。当时的命名完全符合词表（待命/Hold），事故仍然发生——
英文 hold 的"搁置/暂停"先验压过了文档定义，而 stop 的"随时可打断并休眠"能力从未写进文案，模型无从选对。

决定：动作名以模型预训练先验为准，行为语义必须由名字直接承载，文档只补细节不纠偏。
hold 更名 ack（消息系统先验：确认收到、无副作用；词表同步解禁 ack 并把"待命"条目改挂 Ack）；
stop 拆成 sleep（关 pane 保上下文、start 传名字可醒，对应 Dormant/休眠先验）与 kill（除名不可回，
危险动作配危险名字，forget 布尔参数随之删除——同一个动词按开关走向相反结局本就是两个动作）；
新增 interrupt（发 esc 打断 working 子代理的当前回合、会话保留，复用 ADR-0006 中断结算路径，
补上此前为零的 steer 能力；词表禁用 abort，故不叫 abort）。命名之外加机制护栏：对无待发落标记的
非 idle 子代理 ack 直接报错并指向 interrupt/sleep——名字治误读，护栏治假成功。

考虑过且否决：只换中文标签不改动作名（模型看的是英文，治标）；kill 命名休眠动作（语义反转，
比模糊更危险）；interrupt 缓加（用户裁定 steer 缺口真实存在，且实现大半复用中断机制）。
指令中断的在飞标记不持久化：reload 丢标记只退化为外部中断文案，状态机一致，不值得动 schema。
