# FireCode 领域术语

FireCode 让一个指挥官按需委派子代理并保留长任务上下文，配合 fire-review 对抗审查把关质量；
两者互不引用。

## 委派

**指挥官（Master）**：
决定是否委派、如何分派以及如何验收结果的主控 Agent。
_避免使用_：主控、Supervisor、Team Lead

**子代理（Worker）**：
由指挥官启动、承接一段明确工作说明的 Pi 会话。
_避免使用_：工作者、任务、工人（旧称；ADR 的历史记录沿用旧称，不回改）

**子代理池（Worker Pool）**：
当前指挥官可观察和控制的在线子代理与休眠子代理集合；它不记录 Goal、Task 或协作历史。
_避免使用_：团队、任务板、任务队列

**在线子代理（Live Worker）**：
仍有运行进程、可继续接收追问的子代理。
_避免使用_：Active Task、Running Ticket

**休眠子代理（Dormant Worker）**：
进程已释放但 Pi session 仍可恢复的子代理。
_避免使用_：已关闭子代理、归档任务

**工作说明（Delegation）**：
指挥官交给子代理的自包含委派文本，包含任务、交付物、限制和验证要求。
_避免使用_：任务、工单、Assignment Record

**子代理结果（Worker Result）**：
子代理停下时回传给指挥官的最终回复；它是证据输入，不代表指挥官已验收。
_避免使用_：Task Done、Review Passed

**近况（Trace）**：
子代理最近一次外部输入之后的执行轨迹（工具调用、结果、文本与异常停止原因），按预算截断后交给指挥官；它是随时可重取的只读快照，不是完整过程记录，也不代表子代理已停下，读它不构成发落。
_避免使用_：日志、历史、进度

**工单库（Tracker）**：
项目内存放工单的位置（本地 `.scratch/` 或远端 issue tracker，约定见项目 docs/agents/issue-tracker.md），流程中工单的唯一事实源；插件不读写它。
_避免使用_：任务队列、任务板

**工单（Ticket）**：
工单库中的一张垂直切片工单，声明自己的阻塞边；是指挥官生成工作说明的输入，完成即删除或关闭。
_避免使用_：任务、工作说明

**脱管子代理（Unmanaged Worker）**：
在 herdr 里运行但不在子代理池内的 pi 会话（如绕过 subagents 工具用 CLI 启动）；收不到任何回传，不会自动审查，是禁止产生、发现即收编的异常态。
_避免使用_：野子代理、CLI 工人（旧称）

**收编（Adoption）**：
把脱管子代理拉回子代理池的标准流程：让其 pi 退出（会话文件保留），再用 start 传 session 路径拉起，上下文无损、回传恢复。
_避免使用_：接管、恢复（后者指休眠子代理的 resume）

**发落（Disposition）**：
指挥官对一条落定类子代理事件（子代理结果、中断、审查终态、自动续跑提醒）的显式回应：send / review / sleep / kill / ack 之一；未发落会收到一次提醒。
_避免使用_：确认、处置（旧称）

**待拍板（Awaiting Decision）**：
子代理提问经指挥官转述后、等待用户回应的状态；判据为会话落定时子代理池中存在 Herdr blocked 态的子代理（指挥官自行回答会让子代理立即复工，不算）。
_避免使用_：阻塞（那是 Herdr 状态）、等待决策

**待命（Ack）**：
一次性发落动作，表示"已处理这条消息、故意留着备用"；子代理保持原状，对运行中子代理拒绝。
_避免使用_：挂起、暂停、hold（旧称，事故后退役，见 ADR-0007）

**中断（Interruption）**：
子代理回合被中止（指挥官 interrupt 指令、esc 手动介入或连接异常），区别于执行失败：会话与上下文保留，不消耗审查意图，插件续监其后续动静。
_避免使用_：执行失败、abort

**自动续跑（Auto-resume）**：
中断后五分钟无人接手时，插件提醒指挥官续派子代理的机制；续派指令仍由指挥官发出。
_避免使用_：自动重发、心跳

## 对抗审查

**fire-review**：
独立于指挥官的对抗性审查能力，拥有自己的运行状态和结果；只能由会话外部投递 `/fire-review` 触发。
_避免使用_：Master Review Gate、Worker Validator

**审查者（Reviewer）**：
每轮并行挑错的独立 pi 子进程，首行输出 PASS/FAIL；全部 PASS 才算过。
_避免使用_：质检员、子代理

**顾问（Advisor）**：
连续多轮失败后介入的仲裁模型；有界核实驱动裁决的发现，对比多轮失败判断主根因并给出下一步方向，输出裁决而非新发现。
_避免使用_：仲裁员、第四审查者

**裁决（Verdict）**：
顾问的三选一输出：continue（继续修）/ narrow（收窄范围）/ stop（叫停交还用户）。
_避免使用_：判定、结论

**修复回合（Repair）**：FAIL 反馈注入后执行模型自动修复的那一个 turn，以 turn 正常结束判定完成；期间不得委派。
_避免使用_：返工、修复循环（后者指多轮整体）

**占用信号（Occupancy）**：
审查活跃期间经 Herdr 集成频道持有的“会话被占用”标记，防止轮间空闲被误判为结束；只影响显示与监听，失效不伤审查。
_避免使用_：blocked（那是 Herdr 的状态名）

**审查判定（Outcome）**：
从子代理 session 只读解析的终态：通过 / 停止（质量裁决终止，含轮数用尽）/ 审查未完成（error·cancelled·timed_out）/ 进行中 / 无审查；是指挥官了解审查结果的唯一入口。
_避免使用_：裁决（那是顾问的词）

**总结回合（Summary Turn）**：
质量裁决终态（通过 / 顾问叫停 / 轮数用尽）后投给执行模型的收尾回合：用人话总结修了什么、如何通过或为何收敛不了，带反循环禁令；事故终态不触发。
_避免使用_：收尾报告、总结卡（卡另指结果卡）

## 配置

**运行配置（Runtime Configuration）**：
当前 Pi Agent 安装拥有的 FireCode 私人配置，是运行行为的唯一事实源；由安装流程生成，不随源码发行。
_避免使用_：源码配置、默认配置

**配置模板（Configuration Template）**：
可公开解析的运行配置起始样例；复制并按安装环境补全后才成为运行配置，本身不参与运行。
_避免使用_：运行配置、默认配置

**选型表（Model Roster）**：
config.jsonc 里指挥官派工时的模型依据（模型 id + 默认档位 + 适用场景），注入提示词；建议值，用户显式指定优先。
_避免使用_：花名册、模型清单
