# FireCode 领域术语

FireCode 让指挥官按需委派进程内子代理并保留长任务上下文，配合 fire-review 对抗审查把关质量；
观察员独立检查指挥官回合，三者各自注册。

## 委派

**指挥官（Master）**：
决定是否委派、如何分派以及如何验收结果的主控 Agent。
_避免使用_：主控、Supervisor、Team Lead

**子代理（Worker）**：
由指挥官启动、承接一段明确工作说明的 Pi 会话。
_避免使用_：工作者、任务、工人（旧称；ADR 的历史记录沿用旧称，不回改）

**子代理池（Worker Pool）**：
当前指挥官可观察和控制的子代理档案集合；热会话可立即工作，冷档案在 send 时透明打开。它不记录 Goal、Task 或协作历史。七个 `subagents` 命令改变或读取指定子代理，零参数 `subagents_list` 只查询池快照。
_避免使用_：团队、任务板、任务队列

**观察员（Watcher）**：
独立于指挥官与对抗审查的只读观察会话；按主会话增量检查跑偏、过度工程与漏收口，只在这条话此刻送达会改变指挥官下一步动作时开口。发言是单通道的：一条带 `<firecode_watcher>` 来源信封的普通消息，走与子代理结果同构的统一投递（忙时句缝卡片，歇透时前门唤起）。
_避免使用_：审查者、子代理、Supervisor

**工作说明（Delegation）**：
指挥官交给子代理的自包含委派文本，包含任务、交付物、限制和验证要求。
_避免使用_：任务、工单、Assignment Record

**子代理结果（Worker Result）**：
子代理停下时回传给指挥官的最终回复；它是证据输入，不代表指挥官已验收。机器投递在模型上下文中带 `<firecode_master_event>` 来源信封，展示卡仍投影原始正文。
_避免使用_：Task Done、Review Passed

**近况（Trace）**：
子代理最近一次外部输入之后的执行轨迹（工具调用、结果、文本与异常停止原因），按预算截断后交给指挥官；它是随时可重取的只读快照，不是完整过程记录，也不代表子代理已停下，读它不构成发落。
_避免使用_：日志、历史、进度

**工单库（Tracker）**：
项目内存放工单的位置（本地 `.scratch/` 或远端 issue tracker，约定见项目 docs/agents/issue-tracker.md），流程中工单的唯一事实源；插件不读写它。
_避免使用_：任务队列、任务板

**工单（Ticket）**：
工单库中的一张垂直切片工单，声明自己的阻塞边；是指挥官生成工作说明的输入，完成即删除或关闭。
_避免使用_：任务、工作说明

**角色（Role）**：
指挥官派发子代理的固定职业词汇，仅有调研员、工程师、全栈、架构师、设计师、哨兵六种；角色表为已启用的角色绑定主模型原子、适用场景与可选 fallback 链。start 必须指定已配置角色，send 可切换角色。
_避免使用_：模型别名、预设

**哨兵角色（Sentinel Role）**：
专门盯守 CI、部署与长测试等等待过程的低成本角色；结果自动送达，让指挥官回合保持可用。
_避免使用_：轮询票、观察员（后者观察主会话）

**脊柱（Spine）**：
并行实现前由单一写者先落定的共享接口、类型、Schema 或注册表；脊柱完成后，其余垂直切片按冻结边界并行，每个共享文件只有一个写者。
_避免使用_：公共任务、协调层

**fallback 链（Fallback Chain）**：
角色主模型原子之后的有序备用原子，最多两项。只在额度或计费耗尽、模型不可用或宿主重试用尽的持续 5xx 时于同一会话依次切换；切换可见，链用尽明确报错。
_避免使用_：质量路由、瞬时限流重试、静默降级

**收割（Harvest）**：
指挥官提取调研或盯守结果的可复用要点后立即 kill；实现子代理保留到集成与收口完成。
_避免使用_：清理、归档

**发落（Disposition）**：
指挥官对一条落定类子代理事件（子代理结果、中断、审查终态、自动续跑提醒）的显式回应：send / review / kill / ack 之一；未发落会收到一次提醒。
_避免使用_：确认、处置（旧称）

**审查义务（Review Obligation）**：
由 start/send 的 `review:true` 挂在票上的持久承诺；代码保证义务在履行或整票 kill 前不灭，指挥官负责判断何时显式 review。
_避免使用_：自动审查、审查触发器

**待拍板（Awaiting Decision）**：
存在待发落事件且指挥官空闲、需要用户决定下一步的时点；用于 Bark 提升通知优先级，不是子代理状态。
_避免使用_：阻塞、等待决策

**待命（Ack）**：
一次性发落动作，表示"已处理这条消息、故意留着备用"；子代理保持原状，对运行中子代理拒绝。
_避免使用_：挂起、暂停、hold（旧称，事故后退役，见 ADR-0007）

**中断（Interruption）**：
子代理回合被中止（指挥官 interrupt 指令、esc 手动介入或连接异常），区别于执行失败：会话与上下文保留，不消耗审查意图，插件续监其后续动静。
_避免使用_：执行失败、abort

**自动续跑（Auto-resume）**：
中断后五分钟无人接手时，插件提醒指挥官续派子代理的机制；续派指令仍由指挥官发出。
_避免使用_：自动重发、心跳

## 对抗审查

**fire-review**：
独立于指挥官的对抗性审查能力，拥有自己的运行状态和结果；只能由会话外部投递 `/fire-review` 触发。修复反馈、总结提示与状态消息进入模型上下文时统一带 `<firecode_review>` 来源信封。
_避免使用_：Master Review Gate、Worker Validator

**审查者（Reviewer）**：
每轮并行挑错的独立进程内会话，首行输出 PASS/FAIL；全部 PASS 才算过。
_避免使用_：质检员、子代理

**顾问（Advisor）**：
连续多轮失败后介入的仲裁模型；有界核实驱动裁决的发现，对比多轮失败判断主根因并给出下一步方向，输出裁决而非新发现。
_避免使用_：仲裁员、第四审查者

**裁决（Verdict）**：
顾问的三选一输出：continue（继续修）/ narrow（收窄范围）/ stop（叫停交还用户）。
_避免使用_：判定、结论

**修复回合（Repair）**：FAIL 反馈注入后执行模型自动修复的那一个 turn，以 turn 正常结束判定完成；期间不得委派。
_避免使用_：返工、修复循环（后者指多轮整体）

**占用信号（Occupancy）**：
fire-review 活跃期间经 Herdr 集成频道持有的“会话被占用”展示标记；只属于审查模块，失效不改变审查状态机。
_避免使用_：审查状态

**审查判定（Outcome）**：
从子代理 session 只读解析的终态：通过 / 停止（质量裁决终止，含轮数用尽）/ 审查未完成（error·cancelled·timed_out）/ 进行中 / 无审查；是指挥官了解审查结果的唯一入口。
_避免使用_：裁决（那是顾问的词）

**总结回合（Summary Turn）**：
质量裁决终态（通过 / 顾问叫停 / 轮数用尽）后投给执行模型的收尾回合：用人话总结修了什么、如何通过或为何收敛不了，带反循环禁令；事故终态不触发。
_避免使用_：收尾报告、总结卡（卡另指结果卡）

## 配置

**运行配置（Runtime Configuration）**：
当前 Pi Agent 安装拥有的 FireCode 私人配置，是运行行为的唯一事实源；由安装流程生成，不随源码发行。
_避免使用_：源码配置、默认配置

**配置模板（Configuration Template）**：
可公开解析的运行配置起始样例；复制并按安装环境补全后才成为运行配置，本身不参与运行。
_避免使用_：运行配置、默认配置

**角色表（Role Roster）**：
config.jsonc 的 `master.roles` 对象：键只能取六个固定角色，可配置其中任意非空子集；每个已配置角色绑定一个 `provider/model/thinking` 主原子、适用场景与可选 fallback 链，并注入指挥官提示词。同一模型可供多个角色复用。
_避免使用_：选型表、花名册、模型清单
