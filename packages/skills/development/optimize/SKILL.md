# Optimize（优化审计入口）

"还有优化空间吗"有两种完全不同的意图，终止判据互不兼容，所以先分流再执行：


| 意图信号                        | 分支                               | 终止判据                       |
| --------------------------- | -------------------------------- | -------------------------- |
| 清干净、收口、冗余、验收、"改完了检查一下"      | [CLOSEOUT.md](./CLOSEOUT.md)（减法） | 封闭清单扫完 → "审计通过，无收口点"       |
| 更强、更前沿、更未来、对标 XX、业界怎么做、最佳实践 | [ELEVATE.md](./ELEVATE.md)（加法）   | 机会必须有出处 → "已对齐当前最佳实践，无提升点" |


## 分流规则

分支文档的完成门是硬合同。用户已经要求审计时，本轮必须交付字段完整的报告；禁止只给摘要，再用“如果需要我可以继续”把收口、验证、收益、成本或排序推迟到下一轮。

- 意图明显：直接进对应分支，不用问
- 意图不明（就一句"还有优化空间吗"）：问一句——"验收干净（减法）还是功能提升（加法），还是都要？"
- **都要：先减后加**——先把现状清干净，再对标找差距；对标一堆本该删掉的代码是浪费调研
- 两个分支的终止判据不许互相污染：减法扫完不许用加法机会凑数，加法调研完不许顺手列减法问题
