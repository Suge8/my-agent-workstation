# 加法分支：Elevate（对标提升）

加法审计。减法分支问"这次改动干净了吗"——有客观终点；elevate 问"这个东西离业界最好还有多远"——天然没有终点。所以本 skill 用**外部事实源锚定**：每个提升机会必须有出处，禁止凭想象发明工作。模型空想的"可以更好"是永动机，对标事实源的"别人这样做、我们没有、差距是 X"才是情报。

## 流程

### 1. 定义对象和它的 job

这个模块/功能/提示词是给谁解决什么问题的，一两句写下来。后面每个机会都要回答"这对 job 有什么用"——不服务 job 的提升是炫技，不列。

### 2. 调研事实源（真的去查，不靠训练记忆）

- 官方文档、发布说明、路线图 → context7 / exa（`--fresh`：找的是"当前"最佳实践，旧知识可能已过时）
- 同类项目/竞品的源码和设计 → exa 搜 GitHub 真实实现；用户点名的竞品必读
- 研究、行业报告、深度文章 → exa / brave

调研范围先报给用户一句话（查了什么、没查什么），防止事实源本身有盲区。

### 3. 差距分析

逐项对比：我们的做法 / 事实源的做法 / 差距的实际影响。做法相同或我们更优的项也要列出来一句话——"已领先"的确认和"落后"的发现同样有价值。

## 输出格式

按 高收益低成本 → 高收益高成本 → 其余 排序：

```
### 机会 · <一句话>
现状：我们现在怎么做的
对标：<谁> 怎么做的（出处链接/文件）
收益：对 job 的实际提升
成本：粗估（小时级/天级/周级）
建议：做 / 不做（附 YAGNI 理由）/ 需要原型验证（转 prototype）
```

结尾必须有"不建议做"名单——调研中发现但判断不值得的项，附一句原因。敢劝退和敢推荐同样重要。

完成门：每个推荐机会必须分别写全**现状、对标、出处、收益、成本、建议**六项；不能用一段总说明代替逐项成本或出处。输出前逐项检查，缺任一字段的机会要补齐或删除。

## 终止判据

- 每个机会必须有出处。"我觉得可以更好"不是机会，是想象
- 调研完成且无实质差距 → **必须回答："已对齐当前最佳实践，无提升点。"**
- 用户挑了才做；做完的项走 [CLOSEOUT.md](./CLOSEOUT.md) 收尾 + set-test-chain 取证
- 同一对象重复 elevate：只报上次之后事实源的新变化（新版本、新竞品、新研究），不重炒旧机会
