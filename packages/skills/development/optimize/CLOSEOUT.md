# 减法分支：Closeout（收口审计）

封闭式审计，不是开放式头脑风暴。**只扫下面 7 项，禁止发明清单外的新维度。** 本 skill 只做减法（干净、收口）；用户想要加法（功能更强、对标前沿）时转 [ELEVATE.md](./ELEVATE.md)。

为什么要封闭：对"还有优化空间吗"这种开放问题，模型永远能现场编出新工作——打磨循环的终点会由想象力而不是需求决定。这个 skill 的价值一半在于敢说"没有了"：清单有边界，审计才有终点，用户才能下班。

## 范围

默认 = 本次会话改动涉及的模块及其直接调用方。用户明确指定范围时用用户的。不做全仓扫描；纯架构深化交给 improve-codebase-architecture。

## 清单（逐项扫，每项给结论，不许跳）

1. **兼容冗余**：旧路径残留、迁移期兼容分支、未引用 export、孤儿 import、注释掉的代码
2. **多事实源**：同一状态/配置/Schema 在多处定义或多入口写入
3. **分裂实现**：同一职责多个入口、复制粘贴的平行逻辑，能收口成一个的
4. **防御性补丁**：消费端 guard、静默降级、吞错、假成功——症状掩盖而非根因
5. **轮询/sleep**：本该事件驱动（订阅/回调/watcher）的地方在忙等
6. **魔法值**：有业务语义或重复出现的裸常量
7. **空泛命名**：data/info/handler/manager、单字母、误导性名字

## 输出格式

报告开头一行范围声明：扫了哪些文件、跳过了什么。

**P0（正确性风险）和 P1（结构收口）用完整块**——信息量以"用户不打开代码就能拍板"为准：

```
### P1 · src/pairing/relay.ts:142 — 旧 hub 代理路由残留
证据：registerHubProxyRoutes() 仅被已删除的 LegacyPairing 引用，rg 确认无其他调用方
影响：约 120 行死代码 + 一条不再触达的网络路径，误导后续维护
收口：删除该函数及 3 个私有 helper，同步删 routes.test.ts 对应用例
验证：rg registerHubProxyRoutes 零结果，测试套件通过
```

**P2（打磨：命名、魔法值）一行即可**：`P2 文件:行 — 问题 — 方案`

完成门：每个 P0/P1 必须分别写全**证据、影响、收口、验证**四项；不得用合并叙述省略字段，也不得只指出问题不告诉用户如何确认收口完成。输出前逐项检查，缺一项就补齐。

分级标准：P0 = 多事实源、吞错、竞态等正确性风险；P1 = 冗余、分裂实现、防御补丁、轮询；P2 = 命名、魔法值。

没有证据（具体文件+行号+调用方确认）的发现不许列——"感觉可以更好"不是发现。

## 终止判据（本 skill 的核心）

- 清单扫完且无 P0/P1 → **必须以这句话结尾："审计通过，无收口点。"** 可附 P2，但要标明"不做也完全可以"
- 禁止用 P2 凑数制造"还有工作"的假象
- 禁止建议"为未来可能的需求重构"、"可以再抽象一层"——YAGNI
- 同一模块第二次审计：只报上次审计之后新改动引入的问题；重复上次已豁免的项 = 违规。收敛是审计的义务，不收敛的审计是骚扰

## 执行

先报告，不动手。用户挑了哪些项，再修哪些；修完只重扫被修的项及其直接影响面，不重开全量审计。
