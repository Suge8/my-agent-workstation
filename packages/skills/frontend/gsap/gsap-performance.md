# GSAP 性能
## 何时使用此技能
在优化 GSAP 动画以获得流畅的 60fps、降低布局/绘制成本时，或者在用户询问性能、卡顿或快速动画的最佳实践时应用。
**相关技能：** 使用**gsap-core**（变换、autoAlpha）和**gsap-timeline**构建动画；有关 ScrollTrigger 性能，请参阅 **gsap-scrolltrigger**。
## 更喜欢变换和不透明度
动画**变换**（`x`、`y`、`scaleX`、`scaleY`、`rotation`、`rotationX`、`rotationY`、`skewX`、`skewY`）和**不透明度**可以在合成器上继续工作并避免布局和大多数绘制。当变换可以达到相同效果时，请避免对布局密集的属性进行动画处理。
- ✅ 首选：**x**、**y**、**缩放**、**旋转**、**不透明度**。
- ❌ 尽可能避免：**宽度**、**高度**、**顶部**、**左侧**、**边距**、**填充**（它们会触发布局并可能导致卡顿）。
GSAP 的 **x** 和 **y** 默认使用变换（translate）；使用它们而不是**左**/**上**进行移动。
## 将会改变
在 CSS 中对将产生动画的元素使用 **will-change**。它提示浏览器提升该层。
```css
will-change: transform;
```
## 批量读取和写入
GSAP 在内部批量更新。将 GSAP 与直接 DOM 读/写或布局相关代码混合时，请避免以导致重复布局抖动的方式交错读写。最好先执行所有读取，然后执行所有写入（或者让 GSAP 一次性处理写入）。
## 许多元素（交错、列表）
- 当动画相同时，使用 **stagger** 而不是许多带有手动延迟的单独补间；它更有效率。
- 对于长列表，请考虑**虚拟化**或仅对可见项目进行动画处理；如果导致卡顿，请避免创建数百个同时补间。
- 尽可能重用时间表；避免每帧创建新的时间线。
## 经常更新的属性（例如鼠标追随者）
对于经常更新的属性（例如鼠标跟随器 x/y），首选 **gsap.quickTo()**。它重用单个补间，而不是在每次更新时创建新的补间。
```javascript
let xTo = gsap.quickTo("#id", "x", { duration: 0.4, ease: "power3" }),
    yTo = gsap.quickTo("#id", "y", { duration: 0.4, ease: "power3" });

document.querySelector("#container").addEventListener("mousemove", (e) => {
  xTo(e.pageX);
  yTo(e.pageY);
});
```
## ScrollTrigger 和性能
- **pin: true** 提升固定元素；仅固定需要的内容。
- **scrub** 具有较小的值（例如 `scrub: 1`）可以减少滚动期间的工作；在低端设备上进行测试。
- 仅当布局实际更改时（例如内容加载后）调用 **ScrollTrigger.refresh()**，而不是每次调整大小时调用；尽可能去抖。
## 减少同时工作
- 当屏幕外或不活动的动画不可见时（例如，当用户离开时），暂停或终止它们。
- 避免同时为许多元素上的大量属性设置动画；如果需要，可以简化或排序。
## 最佳实践
- ✅ 动画**变换**和**不透明度**；仅在 CSS 中对动画元素使用 **will-change**。
- ✅ 当动画相同时，使用 **stagger** 而不是许多带有手动延迟的单独补间。
- ✅ 使用 **gsap.quickTo()** 来获取频繁更新的属性（例如鼠标追随者）。
- ✅ 清理或杀死离屏动画；当布局更改时调用 **ScrollTrigger.refresh()**，尽可能消除抖动。
## 不要
- ❌ 当 **x**/ **y**/ **scale** 可以实现相同的外观时，对**宽度**/ **高度**/ **顶部**/ **左侧**进行动画处理。
- ❌ 在每个元素上设置 **will-change** 或 **force3D** “以防万一”；用于实际有动画效果的元素。
- ❌ 创建数百个重叠的补间或滚动触发器，无需在低端设备上进行测试。
- ❌忽略清理；杂散补间和 ScrollTriggers 继续运行，可能会损害性能和正确性。
