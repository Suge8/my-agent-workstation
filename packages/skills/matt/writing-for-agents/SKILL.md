为 agent 消费的任何文档提供参考——skill、`AGENTS.md` / `CLAUDE.md`，以及通过指针到达的文档。打包方式不同；写法相同：同一组杠杆让每次运行都采取相同的 _过程_，而不是产出相同的结果。

当你编写的文档是一个 skill 时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式选择和路由 skill。

## 上下文指针

**上下文指针**是 agent 上下文中的一个引用：它命名某些不在当前上下文中的材料，并编码触达这些材料的条件。skill 的 description 是一种指针；`AGENTS.md` 中命名某个文档的一行也是同一个对象。决定 agent 何时触达材料的是指针的 _措辞_，而不是目标——以及触达的可靠程度。一个必须使用的目标藏在措辞薄弱的指针后面，是一个方差 bug：先强化措辞，只有强化失败时才将材料内联。

指针承担两项工作——说明材料是什么，并列出应触发触达它的**分支**（分支是文档处理的一个独立情形，因此不同运行会沿文档采取不同路径）。每一个始终加载的指针词语都在每个回合产生代价，因此它需要比正文更严格的裁剪：

- **将前导词放在最前面**——指针正是在那里完成触发工作的。
- **每个分支只保留一个触发词。** 为同一个分支改写同义词就是把一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删掉正文已经承载的身份信息。**

## 两种负载

你添加的每个文档和指针都会消耗两种预算之一：

- **上下文负载**——始终加载到 agent 窗口中的材料所产生的成本：`AGENTS.md` 中的一行、skill description，以及每个回合都在上下文中的任何内容，无论是否触发都会消耗 token 和注意力。
- **认知负载**——人类承担的成本：哪些文档存在，以及何时触达每个文档。人是索引。这不是需要最小化的成本——它是人类自主性的代价；在人类判断有价值的地方使用它，在没有价值的地方移除它。

只有通过指针触达的材料可以逃脱上下文负载，但要付出指针自身那一行的代价；完全没有指针的材料则全部由认知负载承担。

## 信息层级

一份文档由两类内容组成——agent 执行的有序动作，即**步骤**，以及按需查阅的定义、规则、事实，即**参考资料**——它们可以自由混合：全是步骤（配方）、全是参考资料（评审规则，本 skill），或两者兼有。核心决策是每一块内容在信息层级中的位置，这是一架按 agent 需要材料的即时程度排列的梯子：

1. **文件内步骤**——首要层级：agent 按顺序执行的内容。
2. **文件内参考资料**——按需查阅。通常可以是一个合法的扁平同级集合（评审的每条规则都在同一层）——这是良好安排，不是异味。
3. **已披露参考资料**——移到单独文件中，通过上下文指针触达，仅在指针触发时加载。它可以是同一文件夹中的兄弟文件，也可以是任何位置、任何文档都能指向的完全外部参考资料。

下移太少，顶部会膨胀；下移太多，agent 实际需要的材料会被藏起来。这种张力就是整个决策。

**渐进式披露**就是沿梯子下移——把内容移出主文件并藏在指针后面，让顶部保持清晰。它主要不是 token 优化，而是保护层级的方式。分支是最干净的披露测试：每个分支都需要的内容内联，只有部分分支会到达的内容放到指针后面。当文档包含步骤时，应被披露的文件内参考资料会埋没步骤，使 agent 是否注意到它变成抛硬币——这是方差杠杆，而不只是可读性问题。

**共置**是文件内的配套原则：梯子决定一块内容应处于多深的位置，共置决定它到达该层后应与什么并列。把一个概念的定义、规则和注意事项放在同一标题下，而不是散落各处，让阅读其中一部分时邻近内容也一并出现。测试方法：文档应读起来像是为 agent 编写的文档——分组的材料是这样，散落的材料不是。（这不同于重复：重复是在两个地方表达同一个含义；散落是把一个含义拆碎到多个地方。）

**蔓延**是这里的失败模式：一份文档太长，即使每一行都仍然有效且独特。过多内容会稀释注意力，每增加一行，就多一行需要保持相关。解法是梯子：将参考资料通过指针披露，并按分支或顺序拆分，让每条路径只携带所需内容。

## 步骤与完成标准

每个步骤都以一个**完成标准**结束——告诉 agent 工作已经完成的条件。两项属性使它成为杠杆：

- **清晰度**——agent 能否区分完成与未完成？含糊的界限（“达到理解”）会诱发**过早完成**：在真正完成前结束步骤，注意力滑向 _已经完成_。仍在前方可见的步骤——**完成后的步骤**——提供拉力；标准的清晰度提供阻力。按以下顺序防护：**先收紧界限**（局部且廉价）；只有当界限无法消除地模糊，_并且_你观察到抢跑时，才通过拆分顺序隐藏后续步骤——而隐藏只有跨越真实上下文边界才有效（交接或派发子 agent；内联调用会让后续步骤留在上下文中，什么也不会清除）。
- **要求度**——它要求多少工作。“每个被修改的模型都已核对”会强制彻底工作，而“产出变更列表”不会。要求度驱动**实地工作**——agent 在工作中完成的挖掘，隐藏在措辞中而不是作为独立步骤写出——而且它不受步骤限制：“每条规则都已应用”约束一组扁平的参考资料，正如“每个步骤都已完成”约束一个序列；这就是全是参考资料的文档仍然能够承载穷尽性门槛的原因。

最强的标准既可检查，又具备穷尽性。

## 何时拆分

将一份文档拆成两份会消耗两种负载之一，因此只有拆分有收益时才拆：

- **按顺序拆分**——拆出一串步骤，其中完成后的步骤会诱使 agent 催促完成当前步骤。让它们不可见，会推动 agent 在当前任务上做更多实地工作。注意反向情况：合并序列会让每个步骤暴露给它后面的步骤，诱发过早完成。
- **按调用方式拆分**——skill 专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 前导词

**前导词**是一个已经存在于模型预训练中的紧凑概念，agent 在执行文档时会用它思考（_lesson_、_fog of war_、_tracer bullets_）。它作为 token 被重复使用，而不是作为句子重复使用；这样会累积分布式定义，并通过调动模型已有的先验，用最少 token 锚定一整片行为区域。在你清楚定义它的前提下，自创词也可以，但杜撰的词不会调动任何先验——你要付出定义 token 的成本，而预训练词可以免费提供这些成本；优先使用已有词。

它会锚定两次。在正文中，它负责 _执行_：每次出现这个词，agent 都会触达相同的行为；在扁平参考资料中，它让 agent 将注意力集中到要寻找的一类事物上。在指针中，它负责 _调用_：当同一个词存在于你的提示词、文档和代码库中时，agent 会把共享语言与材料联系起来，更可靠地触达材料。

寻找使用前导词重构的机会。一个三元组在三个位置被完整写出，一个指针花费一句话来指向一个想法——每一个都是恳求压缩成单个 token 的段落：

- “fast, deterministic, low-overhead” → _tight_（一个 _tight_ 循环）。
- “a loop you believe in” → _red_——模糊的门变成二元可观察状态（bug 出现时循环变为 _red_，否则不会）。

你会赢两次：token 更少，并且有一个更锋利的挂钩供 agent 挂住思考。假设每份文档都包含等待清理的复述——去找到它们。

**否定**是这个杠杆旁边的失败模式：用禁止来引导，会把被禁止的行为拖进上下文，使它更容易出现而不是更难出现。_不要想大象_，而大象就是全部内容；否定只是一个弱修饰语，会被强烈激活的概念压过，因此禁令读到一半就像是在指示去做那件事。请提示**正向行为**——陈述目标行为（“写单行注释”），这样被禁止的行为根本不会被说出。只有无法用正向方式表达的硬性护栏，才值得使用禁止；即便如此，也要配上正向目标，让注意力落在该做什么上。

## 裁剪

- 让每个含义都只有一个**单一事实源**：一个权威位置，这样修改行为时只需编辑一处。**重复**——同一个含义出现在多个位置——会增加维护和 token 成本，并将含义在梯子上的显著性膨胀到超过其真实层级。（前导词的偶然反面是有意重复 token，从来不是重复含义。）
- **环境**也是事实源——`package.json` 脚本、配置文件、目录布局、`--help` 输出——而重新陈述它的文档就是一个**缓存**：查找副本，只有查找成本昂贵时才值得负载。缓存 agent 无法通过查看找到的内容：未写明的约定、某个选择背后的原因、配置没有承认的陷阱。把单文件、单命令的查找留给环境，它们在那里不会过时。
- 逐行检查**相关性**：它是否仍然与文档的作用有关？一行内容可能从未与任务有关（纯粹的说明，或应该披露的分支），也可能因它描述的行为或世界发生变化而过时。文档越短，越容易保持相关。如果没有裁剪纪律，默认结局就是**沉积物**：过时的层一层沉下去，因为添加让人安心，删除让人担心，直到你必须穿过它们挖到核心，才能找到仍然有效的内容。
- 逐句寻找**无操作**：模型默认就会遵守的指令，花费负载却什么也没说。测试方法——它是否会相对于默认行为改变行为？——取决于模型，而不是读者：两个对无操作有分歧的人，其实是在对默认行为有分歧，应通过运行文档而不是争论来解决。当一句话不通过测试时，删除整句，而不是只删减其中的词。这个测试同样适用于前导词：一个弱到无法胜过默认行为的词（agent 已经有点彻底了，却写“要彻底”）是无操作；修复方式是使用更强的词（_relentless_），而不是换一种技术。
